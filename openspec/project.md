# Project Context

## Purpose

emaki (sensei-hq): motion stories from one set of JSON scenes — article figures, story players, and narrated
videos in every language. A bun-workspaces monorepo for the `@senseihq/emaki*` npm packages, the `emaki` CLI,
and the emaki Claude plugin.

## Tech Stack

- Core `@senseihq/emaki`: framework-free TypeScript (`tsc` → `dist`), jsdom specs
- Wrappers: Svelte 5 (`emaki-svelte`), React (`emaki-react`), Vue 3 (`emaki-vue`)
- CLI (`emaki-cli`): plain ESM JavaScript (`sade`), plus a Python poster
- Site: SvelteKit; tests: vitest; video: ffmpeg + Playwright/Chromium capture
- Deploy: Cloudflare Workers (site), npm (packages, one version for all)

## Project Conventions

### Code Style

- TypeScript strict; small modules with a `//` header comment; specs colocated in `spec/`
- The core imports no UI library; framework wrappers stay thin (state and DOM work in the core:
  `createShow`, `attachScene`, `ScenePlayerState`)

### Architecture Patterns

- A scene is a pure function of time; JSON scenes first, JS scenes are the escape hatch
- Content is films + stories JSON, read through `FilmSource`/`ContentSource` (Vite globs or fetch)
- Scenes mount in shadow roots (film CSS never meets page CSS); layouts: landscape, portrait, figure

### Testing Strategy

- TDD: write the failing test first, watch it fail, then implement
- 100% lines/branches/functions/statements over `packages/*/src` (vitest V8 coverage; CI fails below)
- `bun run check` = build all + typecheck all + full suite; `svelte-check` for the Svelte package;
  the site has its own suite including browser specs

### Git Workflow

- Work lands via PRs to main (Workers Build previews per PR); GitHub releases run on tags
- `bun run bump` versions every package together; never edit versions by hand

## Domain Context

- A film = scenes (authored on a 16:9 board) + score + voiceover takes + timing; layouts: landscape
  (player/video), portrait (9:16), figure (article art only)
- Pipeline: voice → fit → voice-web → render → build (captions ship as .srt/.vtt, burned in only
  with `--captions`) → stage (desk approval) / publish (YouTube/Instagram) → campaign shorts/carousels

## Important Constraints

- Keys and tokens live only in environment variables or CI secrets
- Docs, skills, agents and the website stay synced with source (the site's copies are generated by
  `site/scripts/copy-docs.mjs` and spec-checked)
- Plugin docs refer to the npm packages and the `emaki` command, never to copied kit files

## External Dependencies

- npm registry; Cloudflare (Workers builds/deploys, posting desk); YouTube + Instagram APIs (publish);
  ElevenLabs (TTS takes); ffmpeg + Chromium (render/capture)
